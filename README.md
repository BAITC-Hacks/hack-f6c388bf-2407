# «Аким на 5 часов»

**AI-симулятор управления городом и распределения ограниченного бюджета**

«Аким на 5 часов» помогает городскому управленцу, аналитику или участнику
симуляции проверить, как набор управленческих решений влияет на транспорт,
озеленение, социальную инфраструктуру, безопасность и городские сервисы.

Пользователь получает единый виртуальный бюджет, выбирает пять инициатив и видит
изменения показателей пяти условных районов Астаны. Система рассчитывает итоговый
**Astana Quality of Life Score**, объясняет сильные стороны и риски сценария и
предлагает направления для улучшения.

Все данные проекта синтетические. Результат является учебной моделью, а не
прогнозом реального развития города.

**Команда:** Болатханулы Аймаут, Ушкемпир Дамир, Марат Ерканат.

## Что реализовано

- одинаковый стартовый бюджет **100 условных единиц** для всех пользователей;
- пять направлений развития: транспорт, озеленение, социальная инфраструктура,
  безопасность и городские сервисы;
- каталог из **14 инициатив** с ценой, областью действия, лагом и эффектами;
- выбор ровно пяти разных инициатив с назначением района для локальных мер;
- интерактивный прогноз показателей после каждого изменения сценария;
- автоматический контроль бюджета, повторов, районов, конфликтов инициатив и
  ограничения не более двух мер одного направления;
- учёт лагов реализации, синергий между инициативами и отрицательных эффектов;
- расчёт Astana Quality of Life Score по пяти районам и десяти показателям;
- визуализация районов, направлений, критических показателей и изменений до/после;
- AI-разбор: резюме, сильные стороны, риски, компромиссы и рекомендации;
- детерминированное серверное объяснение, если AI отключён или временно недоступен;
- сохранение черновика сценария в браузере;
- загрузка готового примера и экспорт результата в текстовый отчёт;
- адаптивный интерфейс с клавиатурной навигацией, видимым фокусом, поддержкой
  reduced motion и режима повышенной контрастности.

## Как работает решение

1. Frontend загружает с backend фиксированный бюджет, исходные показатели районов,
   каталог инициатив и правила симуляции.
2. Пользователь выбирает пять решений. Для районной инициативы он указывает район,
   для общегородской мера автоматически применяется ко всем районам.
3. После каждого выбора backend проверяет черновик и возвращает предварительный
   прогноз, доступность остальных мер, стоимость и остаток бюджета.
4. При запуске сценария backend повторно валидирует все пять решений, применяет
   лаги, эффекты и синергии, рассчитывает изменения районов и итоговый Score.
5. Уже рассчитанные числа передаются AI. Модель не рассчитывает Score, а только
   объясняет полученный результат в структурированном формате.
6. Пользователь видит итоговую оценку, положение районов, критические показатели,
   сильные стороны, риски и рекомендации и может скачать отчёт.

Если AI-провайдер не настроен или вернул ошибку, числовой результат не теряется:
интерфейс показывает детерминированное объяснение правил модели.

## Модель оценки

Все десять показателей находятся в диапазоне от 0 до 100, где большее значение
означает лучший результат. Горизонт симуляции — восемь кварталов.

Для инициативы с лагом `L` учитываемая доля эффекта равна:

```text
(8 − L) / 8
```

Оценка района является взвешенной суммой десяти показателей. Среднее по городу
учитывает долю населения районов. Каждый показатель строго ниже 40 создаёт один
штрафной балл:

```text
Astana Quality of Life Score = 0.7 × среднее по городу
                             + 0.3 × оценка слабейшего района
                             − число показателей ниже 40
```

Исходные данные дают среднее по городу `56,86`, оценку слабейшего района `49,18`
и два критических показателя. Базовый Astana Quality of Life Score равен `52,56`.

## Технологии

### Frontend

- TypeScript;
- React 19;
- Vite 6;
- собственная адаптивная CSS-система;
- browser `fetch`, `localStorage` и Blob API для экспорта отчёта.

### Backend

- Python 3.11+;
- FastAPI;
- Pydantic и pydantic-settings;
- Uvicorn;
- HTTPX, JSON Schema и PyYAML в тестах.

### AI

- OpenAI API;
- Responses API;
- Structured Outputs с Pydantic-схемой;
- модель задаётся через `OPENAI_MODEL`, пример конфигурации использует
  `gpt-6-luna`;
- таймаут, кэш успешных ответов и безопасный fallback при ошибках провайдера.

NVIDIA API в текущей версии не используется.

## Архитектура

```text
┌─────────────────────┐
│ React + TypeScript  │
│ выбор и визуализация│
└──────────┬──────────┘
           │ HTTP / JSON
           ▼
┌────────────────────────────┐
│ FastAPI                    │
│ валидация и preview        │
├────────────────────────────┤
│ Детерминированный движок   │
│ бюджет → эффекты → Score   │
└───────┬─────────────┬──────┘
        │             │ только проверенный результат
        ▼             ▼
┌──────────────┐  ┌─────────────────────┐
│ JSON dataset │  │ OpenAI Responses API│
│ районы/меры  │  │ текстовый AI-разбор │
└──────────────┘  └─────────────────────┘
```

Числовые правила находятся только на backend. Frontend не дублирует формулу и
не доверяет собственному подсчёту бюджета. AI также не изменяет и не
пересчитывает числовой результат.

Основные каталоги:

```text
apps/
  api/src/akim_api/        API, движок расчёта и AI-адаптер
  api/src/akim_api/ai/     схема, промпт и клиент OpenAI
  api/tests/               тесты движка, API, AI и контрактов
  web/src/                 React-интерфейс
contracts/
  openapi.yaml             HTTP-контракт
  examples/                проверяемые примеры JSON
data/
  city.json                районы, показатели, веса и базовый Score
  initiatives.json         инициативы, правила, конфликты и синергии
docs/                      архитектура, AI и сценарий демонстрации
```

## Установка и запуск

Инструкция ниже рассчитана на Windows PowerShell. Понадобятся Python 3.11 или
новее, Node.js 20 или новее и npm.

### 1. Клонировать репозиторий

```powershell
git clone https://github.com/BAITC-Hacks/hack-f6c388bf-2407.git
cd hack-f6c388bf-2407
```

### 2. Запустить backend

```powershell
cd apps/api
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[ai,test]"
.\.venv\Scripts\python.exe -m uvicorn akim_api.main:app --app-dir src --reload --host 127.0.0.1 --port 8000
```

Проверка backend:

- health: [http://127.0.0.1:8000/api/v1/health](http://127.0.0.1:8000/api/v1/health);
- Swagger UI: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs).

### 3. Запустить frontend

В отдельном окне PowerShell:

```powershell
cd apps/web
npm ci
npm run dev
```

Приложение будет доступно по адресу
[http://127.0.0.1:5173](http://127.0.0.1:5173). В режиме разработки Vite
перенаправляет запросы `/api/*` на backend по адресу `127.0.0.1:8000`.

### 4. Подключить OpenAI — необязательно

Приложение работает и без внешнего AI. Для получения AI-разбора скопируйте
пример настроек в корневой `.env`:

```powershell
cd ../..
Copy-Item .env.example .env
notepad .env
```

```env
AI_PROVIDER=openai
OPENAI_API_KEY=your_openai_api_key
OPENAI_MODEL=gpt-6-luna
```

После изменения `.env` перезапустите backend. Ключ читается только backend,
игнорируется Git и не передаётся во frontend.

## Как проверить решение

### Проверка через интерфейс

1. Откройте [http://127.0.0.1:5173](http://127.0.0.1:5173).
2. Убедитесь, что отображаются бюджет `100`, пять районов и базовый Score `52,56`.
3. Нажмите **«Пример сценария»**. Интерфейс должен показать пять решений,
   расход `79`, остаток `21` и предварительный Score `55,55`.
4. Нажмите **«Запустить симуляцию»**.
5. Проверьте итоговую оценку, изменения районов и блок анализа. При рабочем
   OpenAI-ключе используется AI-анализ; без ключа показывается модельный разбор.
6. Измените район или удалите инициативу. Прогноз должен пересчитаться, а старый
   итоговый результат — исчезнуть до следующего запуска.
7. После нового расчёта нажмите **«Экспорт отчёта»** и проверьте скачанный файл.

### Проверка API

В репозитории находится фиксированный пример стоимостью `95`. Для него ожидаются
итоговый Score `56,54`, изменение `+3,98` и отсутствие критических показателей:

```powershell
$scenario = Get-Content .\contracts\examples\score_request.json -Raw
$result = Invoke-RestMethod `
  -Uri http://127.0.0.1:8000/api/v1/scenario/evaluate `
  -Method Post `
  -ContentType "application/json" `
  -Body $scenario

$result | Select-Object score, baseline_score, score_delta, critical_pairs, ai_status
```

При настроенном OpenAI ожидается `ai_status = available`. Без ключа ожидается
`ai_status = disabled`, но Score и `model_analysis` всё равно возвращаются.

### Автоматические проверки

Из корня репозитория:

```powershell
.\apps\api\.venv\Scripts\python.exe -m unittest discover -s apps/api/tests -v
npm --prefix apps/web run build
npm run design
```

Тесты проверяют базовый Score, бюджет, лаги, синергии, несовместимые инициативы,
ограничение направлений, preview, HTTP API, AI-контракт, таймауты и fallback.
Frontend-команда проверяет TypeScript и production-сборку, а `npm run design` —
ключевые требования дизайн-системы и доступности.

## Данные и интеграции

### Данные

Проект использует заранее подготовленный синтетический датасет:

- пять условных районов Астаны и доли населения;
- десять показателей по шкале 0–100;
- веса показателей в формуле;
- 14 городских инициатив;
- стоимость, лаг и эффекты инициатив;
- правила несовместимости и синергии.

Персональные, закрытые или ограниченные данные не используются.

### Внешние сервисы

- **OpenAI API** — необязательное создание текстового разбора результата;
- других внешних API, баз данных и облачных хранилищ текущая версия не использует.

HTTP-маршруты проекта:

- `GET /api/v1/health` — состояние backend;
- `GET /api/v1/scenario/catalog` — бюджет, районы, показатели, инициативы и правила;
- `POST /api/v1/scenario/preview` — проверка и прогноз черновика от нуля до пяти решений;
- `POST /api/v1/scenario/evaluate` — итоговая проверка и расчёт пяти решений.

Полный контракт описан в `contracts/openapi.yaml`.

## Ограничения текущей версии

- данные синтетические и не отражают фактическое состояние районов Астаны;
- результат показывает эффект в рамках фиксированного горизонта восьми кварталов;
- формула не моделирует инфляцию, изменение стоимости проектов, демографию и
  внешние экономические факторы;
- сценарии сохраняются только локально в браузере;
- нет аккаунтов, серверного хранения, рейтинга и сравнения нескольких команд;
- не реализованы случайные городские события и перераспределение бюджета после них;
- не генерируется презентация команды; доступен только текстовый отчёт;
- AI-анализ требует отдельного OpenAI API ключа, сетевого доступа и доступного
  баланса; при его отсутствии используется детерминированное объяснение;
- интерфейс и backend запускаются как два отдельных локальных процесса;
- проект не предназначен для принятия реальных управленческих решений без
  дополнительной валидации модели и данных.

## Развёрнутая версия
