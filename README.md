# «Аким на 5 часов»

AI-симулятор городских решений для Астаны. Пользователь распределяет общий бюджет
между пятью инициативами, видит прогноз по районам и получает объяснение
сильных сторон, рисков и компромиссов.

Все данные в проекте синтетические. Это прозрачная учебная модель, а не прогноз
реальной городской политики.

## Возможности

- Для каждого запуска доступны одинаковые исходные данные и бюджет **100 условных единиц**.
- Нужно выбрать ровно **5 разных инициатив** в направлениях транспорта, озеленения,
  социальной инфраструктуры, безопасности и городских сервисов.
- Интерактивный прогноз пересчитывается после каждого выбора. До отправки сценария
  интерфейс показывает стоимость, остаток, изменения показателей, синергии и причины,
  по которым отдельные варианты недоступны.
- Backend проверяет стоимость, районы, повторы, максимум две меры одного направления
  и несовместимые пары. Невалидный сценарий получает понятный ответ `422`.
- После запуска показываются итоговый **Astana Quality of Life Score**, оценки районов,
  изменение каждого из десяти показателей, вклад мер и синергии.
- AI может объяснить уже рассчитанный сервером результат. При отключённом или
  недоступном провайдере симуляция работает и показывает детерминированный разбор.
- В браузере можно загрузить пример, изменить и очистить сценарий, а после расчёта
  скачать текстовый отчёт.

## Стек и структура

- **Frontend:** React 19, TypeScript, Vite.
- **Backend:** Python 3.11+, FastAPI, Pydantic.
- **AI:** OpenAI Responses API и Structured Outputs; подключение необязательно.
- **Данные:** синтетические JSON-файлы в `data/`.
- **Контракты:** `contracts/openapi.yaml` и примеры запросов/ответов в `contracts/examples/`.

```text
apps/
  api/src/akim_api/       FastAPI, правила, расчёт score, адаптер AI
  api/tests/              тесты движка, API, AI и контрактов
  web/src/                React-интерфейс, прогноз и отчёт
contracts/                OpenAPI и проверяемые JSON-примеры
data/                     единый бюджет, районы, показатели и инициативы
docs/                     архитектура и сценарий проверки
scripts/check-design.mjs  проверка дизайн-токенов и доступности стилей
tools/generate_ai_examples.py  пересборка примеров из движка
```

## Запуск на Windows

Нужны Python 3.11 или новее и Node.js 20 или новее. Команды ниже рассчитаны на
PowerShell и выполняются из корня репозитория.

### 1. Backend

```powershell
cd apps/api
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[ai,test]"
.\.venv\Scripts\python.exe -m uvicorn akim_api.main:app --app-dir src --reload --host 127.0.0.1 --port 8000
```

Проверить, что сервис запущен, можно по адресу [http://127.0.0.1:8000/api/v1/health](http://127.0.0.1:8000/api/v1/health).
Интерактивная документация API: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs).

### 2. Frontend

Откройте второе окно PowerShell:

```powershell
cd apps/web
npm ci
npm run dev
```

Откройте [http://127.0.0.1:5173](http://127.0.0.1:5173). Vite перенаправляет `/api/*` на локальный backend.

### 3. Подключение OpenAI (необязательно)

Без ключа расчёт и объяснения модели доступны полностью; в интерфейсе будет явно
показано, что AI-провайдер не подключён. Для AI-разбора скопируйте `.env.example`
в корневой `.env` и укажите свой ключ и доступную аккаунту модель:

```powershell
Copy-Item .env.example .env
```

В `.env` нужны `AI_PROVIDER=openai`, `OPENAI_API_KEY` и `OPENAI_MODEL`. Ключ читает
только backend, он игнорируется Git и никогда не попадает во frontend. Реальные
вызовы API тарифицируются OpenAI. В текущей версии настроен OpenAI-провайдер;
NVIDIA-токен не используется.

## Как проверить основной сценарий

1. Запустите backend и frontend и убедитесь, что на странице видны исходная оценка
   **52,56**, бюджет **100** и пять районов.
2. Нажмите **«Пример сценария»**. Должно появиться 5 решений, 79 потраченных и 21
   оставшаяся единица бюджета; прогноз изменится до **55,55**.
3. Нажмите **«Запустить симуляцию»**. Появятся районные результаты и объяснения.
   Без ключа AI-статус будет «не подключён», а расчёт и модельный разбор останутся.
4. Удалите меру или поменяйте район: прогноз пересчитается, предыдущий результат
   исчезнет до нового запуска.
5. Попробуйте выбрать шестую инициативу, повторить инициативу или выбрать
   несовместимые меры: интерфейс должен заблокировать выбор либо показать причину.
   Backend также отклоняет недопустимый сценарий с HTTP 422.
6. После успешного расчёта проверьте скачивание текстового отчёта.

Есть и отдельный пример для проверки API. Он задан в `contracts/examples/score_request.json`
и ожидает стоимость **95**, итоговый score **56,54** и изменение **+3,98**:

```powershell
$scenario = Get-Content .\contracts\examples\score_request.json -Raw
Invoke-RestMethod -Uri http://127.0.0.1:8000/api/v1/scenario/evaluate `
  -Method Post -ContentType 'application/json' -Body $scenario |
  Select-Object score, score_delta, ai_status
```

## Проверки разработчика

Из корня репозитория:

```powershell
.\apps\api\.venv\Scripts\python.exe -m unittest discover -s apps/api/tests -v
npm --prefix apps/web run build
npm run design
```

Тесты проверяют базовый score, влияние лагов и синергий, бюджетные и доменные
ограничения, конфликтные инициативы, preview, API-ответы и поведение AI при
отключении или ошибках. Они не обращаются к внешнему AI API. Сборка проверяет
TypeScript и production bundle; дизайн-проверка — токены, адаптивные брейкпоинты,
видимый фокус, режимы повышенной контрастности и минимальный размер текста.

## API и модель

- `GET /api/v1/health` — состояние сервиса.
- `GET /api/v1/scenario/catalog` — общий бюджет, исходные показатели, районы,
  инициативы, правила и базовая оценка.
- `POST /api/v1/scenario/preview` — прогноз для чернового набора от нуля до пяти мер.
- `POST /api/v1/scenario/evaluate` — проверка и расчёт сценария ровно из пяти мер,
  включая AI-разбор при включённой конфигурации.

Для инициативы с лагом `L` из горизонта `H = 8` кварталов учитываемая доля эффекта
равна `(H − L) / H`. Эффекты городских мер применяются ко всем районам; синергии
добавляются отдельно и не уменьшаются из-за лага. Показатели ограничиваются
диапазоном 0–100.

Оценка района — взвешенная сумма десяти показателей. Среднее по городу учитывает
долю населения районов. Каждый показатель ниже 40 добавляет один штрафной балл:

```text
Astana Quality of Life Score = 0.7 × среднее по городу
                             + 0.3 × оценка слабейшего района
                             − число показателей ниже 40
```

Исходные значения дают среднее **56,86**, оценку слабейшего района **49,18** и два
критических показателя в Нуре; поэтому базовый score равен **52,56**. Числовые
результаты всегда рассчитывает backend. LLM получает уже проверенный расчёт и
возвращает только текстовые выводы, риски, компромиссы и рекомендации.
