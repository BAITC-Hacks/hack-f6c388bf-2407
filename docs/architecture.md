# Архитектура и правила симуляции

## Границы пакетов

- `apps/web`: только пользовательский интерфейс и вызовы API. Не дублирует финансовую или scoring-логику.
- `apps/api`: валидирует выбор, рассчитывает бюджет, эффекты и score, формирует объяснение результата.
- `data/`: единый источник исходных районных показателей и каталога мер. Данные синтетические.
- `contracts/openapi.yaml`: источник истины для HTTP-границы; frontend может генерировать типы или использовать совместимые локальные типы.

## API на старте

- `GET /api/v1/health` — состояние сервиса.
- `GET /api/v1/scenario/catalog` — бюджет, горизонт, районы, показатели, меры и правила.
- `POST /api/v1/scenario/evaluate` — проверка и расчёт сценария из ровно пяти решений.

Запросы и ответы подробно определены в `contracts/openapi.yaml`. Невалидный сценарий возвращает HTTP 422 с кодом правила и понятным сообщением; score для него не рассчитывается.

## Детерминированная модель

Исходные значения всех десяти показателей находятся в диапазоне 0–100; больше — лучше. Горизонт `H=8` кварталов. Для меры с лагом `L` реализованная доля эффекта равна `(H-L)/H`. Эффект меры применяется к выбранному району либо всем районам. Эффекты складываются, затем ограничиваются диапазоном 0–100.

Синергии применяются полностью (без поправки на лаг), если выбраны обе меры пары; для районных пар бонус назначается району первой меры. Конфликты, направления и эффекты перечислены в `data/initiatives.json`.

Для района `d`: `D_d = Σ(w_k × I'_dk)`. Веса показателей приведены в `data/city.json` и суммируются в 1. Городской результат `D_avg = Σ(pop_d × D_d)`. Число критических значений `N_crit` — количество пар «район × показатель» со значением строго меньше 40.

`Astana Quality of Life Score = 0.7 × D_avg + 0.3 × min(D_d) − N_crit`.

Для исходных данных ожидается `D_avg ≈ 56.86`, минимальный район `49.18`, два критических значения (S1/S2 в Нуре) и базовый score `52.56`.

## Роль AI

Числовой расчёт и проверка ограничений всегда остаются детерминированными на backend. AI получает уже проверенный результат (изменения показателей, вклад мер, стоимость, остаток, слабые места) и возвращает текстовые сильные стороны, компромиссы, риски и рекомендации. Не просить модель придумывать или пересчитывать значения. Если провайдер отключён или недоступен, API должен вернуть рассчитанный сценарий с пометкой, что AI-объяснение недоступно.

Ключи хранятся только в окружении backend. Провайдер выбирается переменной `AI_PROVIDER`; рекомендуется начать с одного рабочего провайдера и сохранить интерфейс адаптера для переключения OpenAI/NVIDIA без изменений контракта клиента.
